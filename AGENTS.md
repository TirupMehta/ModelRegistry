# ModelRegistry agent notes

Read this file before continuing product work. The roadmap below describes work that is **not complete**; do not claim it is shipped unless the code and live behavior prove it.

## Data and product rules

- Keep lab-published specifications separate from live provider offers. The current provider panel is OpenRouter-only; an unmapped model does not mean unavailable.
- Treat `lastVerifiedAt` as the date a source was reviewed, not a live availability signal. A dataset revision date is not a substitute for field verification.
- When changing model data or public routes, keep the model page, API/OpenAPI, RSS/JSON Feed, metadata, and share previews consistent.
- Comparisons must identify the source, benchmark version, and test conditions. Do not label a model universally “best” from incomparable results.
- A model is not added until its record is complete: nothing blank, every figure cited to a primary source, an unstated figure written as "Undisclosed", and, for a text model, our own score backed by an independent result row with every test filled. `scripts/test-completeness.js` (part of `npm test`) enforces it; new records can never join `scripts/completeness-baseline.json`. Read the evaluator's own page for the numbers, then run `node scripts/refresh-independent.mjs` and expect 0 changed values.
- The public name of the score is **ModelRegistry Score**. "Meridian" is the internal method and file name only ("Meridian score" collides with Google's Meridian marketing tool), so never use it in public text. Each test's `access` (private or public) in `data/independent-benchmarks.ts` comes from the evaluator's own methodology page and feeds the public-versus-private gap; a new test needs its access read from its primary source, and the gap never changes a score. The Meridian method (`lib/meridian.ts`, `lib/standing.ts`) is anchored to frozen calibration constants in `data/meridian-calibration.ts`: adding a model must never change another model's score. After adding a model's independent row, run `node scripts/test-meridian.js --write-ledger` and confirm the ledger diff is only the new line. Do not recalibrate (`scripts/calibrate-meridian.js --write`) for a new model, and do not change the scoring math without bumping `MERIDIAN_VERSION`, recalibrating and rewriting the ledger on purpose. `npm test` enforces all of this.
- The second evaluator is Epoch AI's Epoch Capabilities Index, used only as a cross-check on the ModelRegistry Score (rank correlation and pair agreement on `/score`, the model page, `/api/v1/standing`, markdown and `llms.txt`). It is never an input to the score: it is itself a composite of 50+ benchmarks and trails the newest releases, so mixing it in would double-count tests and change every published number. `data/epoch-eci.ts` is generated: run `node scripts/refresh-epoch.mjs` (expect 0 changed values) after any Epoch update, and add a newly covered model by adding a line to `MAP` in that script, never by editing the data file. Keep the Epoch attribution (CC BY 4.0) and the disclosure that its method paper was funded by Google DeepMind. A model not in Epoch's file is listed as not covered, never estimated.
- Keep the first load light for a visitor on average hardware. Client components never import the dataset as a value: server pages pass the slim `ModelListItem` list from `lib/model-list.ts` (no `fieldSources`, `changeLog` or `sources`), and provenance loads on demand through `components/model-evidence.tsx`, which says when it is loading or unavailable and offers a retry. Never link a feed or API route with Next `<Link>` (it prefetches the target on every page view); use `<a>`. Every `<main>` is the skip-link target (`id="content"`), and any dialog traps focus, closes on Escape and returns focus. `scripts/test-user-experience.js` and the live `scripts/test-routes.js` (homepage script budget, no dataset in first-load JavaScript) enforce this.
- **Never show a half-confirmed label anywhere public.** The site is built on trust: no "partially verified", "unverified", "unconfirmed", "partly checked", counts of such records, or similar wording on any page, API response, feed, OpenAPI schema, markdown, MCP or CLI output. Show only confirmed facts; where nothing is confirmed, show nothing. `verificationStatus` values other than `verified` and `retired` are internal audit state: read them for public output only through `lib/verification.ts`. Gaps are fixed by re-sourcing against the primary source, never advertised. `scripts/test-public-trust.js` (part of `npm test`) fails on this wording; do not add exceptions or work around it.
- Before a record is marked `verified`, run `node scripts/verify-fields.mjs <id>` (name, release date, context, price on cited pages) and `node scripts/verify-claims.mjs <id>` (every number in the highlight and benchmarks on cited pages). A number that cannot be found is reviewed by hand against the primary source, or removed; never keep a claim because an earlier record had it. Do not write traffic or ranking claims (OpenRouter volume, usage share) into a record: they are not lab specifications.
- Model suggestions require maintainer review. A generated GitHub issue does not publish a model.

## Unfinished roadmap

1. **Model Alerts — deferred by the owner.** `/alerts` and the popup currently collect a launch waitlist; they do not send model-change alerts. Wait for the owner to reopen this work. Then define watched models/change types, consent and confirmation, delivery frequency, unsubscribe, deduplication, retries, and retention before building delivery.
2. **Refresh source verification across the registry.** Done on 2026-11-19: all 78 records were re-read field by field against primary pages (70 verified, 8 retired), and `scripts/validate-registry.js` now rejects any record that is not `verified` or `retired`. Keep it current: re-run `node scripts/verify-fields.mjs` and `node scripts/verify-claims.mjs` periodically, refresh records older than 30 days, and re-check promotional prices (several end on a stated date: Gemini introductory prices, MAI Code 2 on 2027-05-17, GPT-5.6 on 2026-11-30, Mercury 3 launch price).
3. **Make model comparisons evidence-complete.** Expand per-model benchmark provenance with source URLs, benchmark/version, date, and evaluation conditions; compare only compatible runs and explain where the evidence cannot support a direct ranking.
4. **Broaden live provider coverage carefully.** The current API fetches OpenRouter endpoint offers for an explicit subset of mapped models. Add other providers only with stable source APIs, explicit model mappings, freshness/cache behavior, clear outage states, and wording that distinguishes provider offers from official lab specifications.
5. **Finish share-preview parity.** Every indexable route now gets Open Graph and Twitter text plus a generated `/api/og` image through `withShare` in `lib/share.ts` (model, lab, best-by-task and page cards from the dataset), enforced by `scripts/test-share.js`. `/compare/[slug]` now shares a true pair image (`/api/og?a=&b=`, both records side by side, no winner declared). Long descriptions are clamped so the card footer never disappears. Still open: per-route image alt text review and checking the rendered cards in a real crawler/validator after each metadata change.
6. **Complete the contribution workflow.** The suggestion form prepares a GitHub issue; it does not validate or create a pull request. Improve maintainer triage, duplicate detection, source checks, and validation before considering a PR generator. Keep publication behind maintainer review.
7. **Add release-grade regression coverage.** Share-preview and public-status parity are covered (`test-share.js`, `test-public-trust.js`), and `test-routes.js` asserts that RSS, JSON Feed and `/api/v1/models` report the same records. Still open: filters and dropdown keyboard/pointer behavior, mobile layouts, provider lookup failures. Preserve honest empty, stale, and unavailable states.
